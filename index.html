HELP / GETTING STARTED

End-user manual

Glow maps packages, services, and their declared dependencies. Start with a demo, then load your own configuration. You do not need Claude or the command-line tool to use this dashboard.

Your first map

  1. Choose a Scenario to try a mixed, healthy, or vulnerable example. All demo findings are illustrative, not a live audit.
  2. Select a block to open its component details. Check Direct dependencies and Update / incident blast radius to see what it uses and what depends on it.
  3. Choose Import config for a local file, or Paste config, select its format, paste the contents, and choose Visualize.
  4. Optionally choose Refresh once for public package and security checks. Read the privacy guidance below before enabling network access.
  5. Choose Export JSON to save the displayed snapshot before leaving. Your configuration is not automatically saved.
Load your own dependencies

Import Glow YAML (.yaml or .yml), package.json, requirements.txt, a C# .csproj, packages.config, or an exported Glow JSON snapshot. Each import is limited to 1 MB and 300 components. Invalid input shows an error and leaves the current graph in place.

For a small connected map, choose Paste config and Glow YAML, then paste this example:

project: My application
dependencies:
  - name: shared-library
    version: "1.0.0"
    status: healthy
services:
  - name: api
    status: running
    dependencies: [shared-library]
  - name: web
    status: running
    dependencies: [api]

This uses an illustrative package name, not verified package or security data. Replace it with your own package and installed version. Package ecosystems are npm (default), PyPI, or NuGet. Every component name must be unique, and every name in a component's dependencies must exist in the same file.

Manifest imports list declared packages but do not resolve installed versions or invent dependency edges. Version ranges remain unresolved. Basic requirements.txt entries are supported; includes, URLs, editable installs, hashes, and environment markers are rejected. Browser C# imports accept unconditional package references, not project references, central package management, or MSBuild evaluation. A bare C# version is a minimum constraint, not an exact installed version.

For a restored .NET solution or Terraform/Bicep plan, use the local CLI converter, then import the generated Glow YAML. The browser does not directly load solutions or raw infrastructure plans.

Install and use the optional .NET CLI

Use the CLI when you need resolved packages and project relationships from a .NET solution, or planned resource changes from Terraform/Bicep. Ordinary YAML and manifest imports do not need it. The CLI runs locally and needs no Node.js or Claude installation.

Install the .NET 10 SDK, then download Glow.Cli.<version>.nupkg and SHA256SUMS from the latest CLI release and check the download with Get-FileHash. This is a GitHub release package, not a package published to NuGet.org.

For example, in PowerShell:

New-Item -ItemType Directory -Path .\glow-release -Force
$release = Invoke-RestMethod https://api.github.com/repos/sujithq/glow/releases/latest
$release.assets | ForEach-Object { Invoke-WebRequest $_.browser_download_url -OutFile ".\glow-release\$($_.name)" }
Get-FileHash .\glow-release\Glow.Cli.*.nupkg -Algorithm SHA256; Get-Content .\glow-release\SHA256SUMS
dotnet tool install --global Glow.Cli --source .\glow-release --framework net10.0
glow --version

The package also supports .NET 11 with a matching runtime; .NET 10 is the stable installation choice. If glow is not found after installing, reopen the terminal and check that the .NET global tools directory is on your PATH. To upgrade, download the new release into the same directory and run dotnet tool update with the same source and framework options.

Convert a trusted .NET solution

dotnet restore "C:\src\App\App.slnx"
glow convert "C:\src\App\App.slnx" --output "C:\src\App\glow.config.yaml"

Both .sln and .slnx work. Restore is a separate action that can execute MSBuild logic: never restore an untrusted project just to visualize it. The converter only reads existing restore assets and does not restore, build, or contact package feeds. For multiple restore targets, add an exact key such as --target net10.0; an error lists the available keys.

Convert infrastructure plan files

First generate Terraform plan JSON with your normal Terraform workflow, or compile Bicep to ARM template JSON and generate Azure what-if JSON separately. Then convert the local files:

glow convert tfplan.json --output terraform.config.yaml
glow convert main.json --what-if what-if.json --output azure.config.yaml

Glow does not run Terraform, contact Azure, apply plans, or deploy resources. Optional --icon-map embeds your own local icon mapping. See the CLI guide for plan generation, icon setup, supported formats, and limitations.

Finally, choose Import config and select the generated YAML. Review it before sharing: project paths, package identities, and resource names can be sensitive. Output files are never overwritten; choose a new output name or move the old file. Missing assets, conflicting versions, and maps exceeding 300 components or 1 MB fail with an error rather than producing a partial map.

Read the views, colors, and summary
  • Health: green means configured healthy; yellow can mean a warning, unverified data, deprecation, a version difference, or an API error; red means critical status or reported vulnerabilities. Healthy does not mean security-cleared.
  • Security: red means reported findings. Green requires a successful exact-version OSV scan with no configured findings. Yellow means unchecked, unresolved, or limited coverage, including services without a package scan. Empty NuGet results remain limited coverage because matching is case-sensitive.
  • Dependency: neutral green shows topology, not security clearance. Reported vulnerabilities can still pulse.
  • Plan: infrastructure imports open here when planned changes are present. Green indicates create, yellow update, red delete, and purple replace; other actions appear in component details. Planned changes are not live health checks, and Glow does not apply them.

Compact boxes are packages; taller two-tier towers are services or projects. The summary counts all loaded components, not just the filtered map. Health totals always use Health rules, even in another view. Reported findings sums reported vulnerability counts, not unique advisory IDs.

Audience is a view shortcut, not access control: Developer and Architect choose Dependency, DevOps chooses Health, and Security chooses Security.

Navigate the map and investigate impact
  • Use Layer to show packages, services, or both. Find filters by component name. Connections disappear when either endpoint is hidden.
  • Use + and − to resize the map, then scroll if needed. This is an isometric diagram, not a rotatable 3D camera.
  • Reset view clears the search, restores all layers and default zoom, and clears the selection. It does not reload data or change the current view.
  • Click a block, or reach it with Tab and press Enter or Space. Hover or keyboard-focus a connection to read which component depends on which.
  • The inspector lists versions, scan status, licenses, advisories, errors, and direct dependencies. Dashed outlines mark direct and indirect consumers of the selected component; use the blast-radius buttons to inspect them.

For an update or incident, select the affected package and review its consumers to plan testing. Impact follows only the relationships supplied in your configuration; it cannot predict breaking changes or prove exploitability. Reduced-motion system preferences disable pulsing.

Live checks and privacy

Importing and exploring files happens locally in your browser. Demo loading fetches bundled example files; registry and security checks remain off until you choose Refresh once or enable Poll every 60 seconds.

A refresh sends package names and versions to public npm/NuGet registries and OSV as applicable, and configured repository: owner/repo names to GitHub. Review private package and repository identities before opting in. No credentials are needed or stored; private feeds are unsupported.

Polling waits 60 seconds after each completed refresh while the page stays open. Turn it off to cancel an in-flight refresh. Loading a valid configuration disables polling and cancels outstanding checks.

Security checks require exact versions. PyPI release metadata is not fetched. GitHub results are combined commit statuses, not all Actions checks or service uptime. Review the last-refresh time, API error count, unresolved/limited scans, and individual component errors; an empty scan is not a security guarantee.

Every refresh starts from the loaded configuration. New live results replace previous live results, but configured findings are retained. Edit the original configuration to remove stale configured evidence after independently verifying a fix.

Save, share, and reopen a snapshot

Export JSON downloads glow-report.json with the current graph, reported findings, scan/error states, and any refresh timestamp. Treat it as potentially sensitive: it contains component identities and relationships.

Use Import config to reopen the JSON. It is normalized as configuration, not trusted as a fresh scan: previous live clearance and timestamps are not restored as current evidence. Keep your original YAML or manifest for future edits. Reloading or closing the page loses unsaved changes and stops monitoring.

Troubleshooting
  • Import failed: check the message above the map or in the paste dialog. Confirm the selected format, file size, unique component names, and that all dependency references exist. Split maps larger than 300 components.
  • Blank or incomplete map: choose Reset view to clear Find and Layer filters. Manifest imports do not supply transitive relationships; add independently verified edges in Glow YAML.
  • Yellow after refreshing: inspect Security scan and component errors. Ranges, unknown versions, limited NuGet coverage, network failures, rate limits, and CORS restrictions do not produce clean scans.
  • Findings remain after an upgrade: check that you loaded the new exact installed version. Configured findings persist until you update the source configuration; verify the original advisory before removing them.
  • Demo cannot load: use the hosted site or serve the built dashboard over HTTP rather than opening the HTML directly from disk. Check the loading error and your connection, or import a local configuration.

For detailed format rules and converter limitations, see the extended usage guide.
